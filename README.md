# HardwareMonitor

Десктопное приложение на WPF (.NET Framework 4.8) для мониторинга основных ресурсов компьютера с получением данных через WMI (Windows Management Instrumentation).

---

## Возможности

**Мониторинг процессора (CPU)**
- Модель, производитель и архитектура процессора
- Количество ядер и потоков
- Текущая загрузка в процентах
- График загрузки в реальном времени

**Мониторинг оперативной памяти (RAM)**
- Общий объём памяти
- Доступная память
- Используемая память
- Процент использования

**Мониторинг дисков**
- Список всех логических дисков (C:, D: и т.д.)
- Общий и свободный объём для каждого диска
- Файловая система
- Процент заполненности

**Системная информация**
- Операционная система и версия
- Архитектура системы (x64/x86)
- Имя компьютера
- Имя текущего пользователя

**Управление процессами**
- Список всех запущенных процессов
- Отображение использования CPU и RAM для каждого процесса
- Возможность завершить выбранный процесс
- Сохранение выделения процесса при автообновлении данных

**Обновление данных**
- Кнопка ручного обновления
- Автоматическое обновление каждую секунду
- Асинхронная загрузка данных без блокировки интерфейса (async/await + Task.Run)

**Экспорт данных**
- Экспорт отчёта о состоянии системы в формате TXT
- Экспорт данных в формате CSV
- Экспорт данных в формате JSON
- Сохранение графика загрузки CPU в PNG

---

## Технологии

- Язык программирования: C#
- Платформа: .NET Framework 4.8
- UI Framework: Windows Presentation Foundation (WPF)
- Архитектурный паттерн: MVVM (Model-View-ViewModel)
- Получение данных: WMI через System.Management
- Асинхронность: async/await, Task.Run
- Сериализация: Newtonsoft.Json

---

## Системные требования

- Операционная система: Windows 10/11 (x64)
- Runtime: .NET Framework 4.8
- Оперативная память: от 4 ГБ
- Свободное место на диске: примерно 100 МБ

## Установка и запуск

Клонировать репозиторий:

    git clone https://github.com/your-username/HardwareMonitor.git

Перейти в папку проекта:

    cd HardwareMonitor

Открыть решение HardwareMonitor.sln в Visual Studio 2019 или 2022.

Убедиться, что установлен .NET Framework 4.8 SDK.

Восстановить NuGet-пакеты через меню Visual Studio: Tools → NuGet Package Manager → Restore NuGet Packages

Собрать проект: Build → Build Solution (или Ctrl+Shift+B)

Запустить приложение: Debug → Start Debugging (или F5)

## Использование

После запуска приложения откроется главное окно с несколькими вкладками:

**Мониторинг CPU**
- В верхней части окна отображается график загрузки процессора
- Под графиком показана подробная информация о процессоре

**Мониторинг памяти**
- Отображается общий объём, доступная и используемая память
- Процент использования памяти

**Мониторинг дисков**
- Таблица со всеми логическими дисками
- Информация об объёме и заполненности каждого диска

**Список процессов**
- Таблица со всеми запущенными процессами
- Колонки: имя процесса, использование CPU (%), использование RAM (МБ)
- Для завершения процесса выберите его и нажмите кнопку "Завершить процесс"

**Управление обновлением**
- Кнопка "Обновить" — принудительное обновление всех данных
- Чекбокс "Автообновление" — включение/выключение автоматического обновления каждую секунду

**Экспорт данных**
- Кнопка "Экспорт" с выпадающим меню
- Выберите формат экспорта: TXT, CSV, JSON или PNG (для графика CPU)
- Укажите место сохранения файла

## Технические детали

**WMI-классы, используемые в приложении:**

- Win32_Processor — информация о процессоре
- Win32_OperatingSystem — информация о памяти и операционной системе
- Win32_LogicalDisk — информация о логических дисках
- Win32_ComputerSystem — общая информация о компьютере

**Производительность:**

- Интервал обновления данных: 1 секунда
- Рекомендуемый интервал для WMI: 1-3 секунды
- Все запросы к WMI выполняются асинхронно через Task.Run
- Пользовательский интерфейс остаётся отзывчивым благодаря async/await

**График загрузки CPU:**

- Отображает последние 50 точек измерений
- Построен с использованием Canvas и Polyline
- Автоматически масштабируется при изменении размера окна

---

## Примечания

- WMI не предназначен для высокочастотного мониторинга (интервал менее 1 секунды). В данном проекте используется интервал в 1 секунду с асинхронной обработкой данных для обеспечения стабильной работы.

- Для завершения некоторых системных процессов может потребоваться запуск приложения от имени администратора.

- При завершении критически важных системных процессов возможна нестабильная работа операционной системы. Будьте внимательны при использовании функции завершения процессов.
